# 算给你看 · 制作约定

- **账号**（10-29 起）：名字「算给你看」，和视频里的章节标、片尾、封面一致；头像三个方案待用户选（`output/算给你看-头像-A/B/C.png`，`videos/account`：A 点阵星球、B 骰子、C 钟形）。头像不放文字：第一版金色"算"字被否（"一个字这也太土了"），图形要和视频同一套颜色，并在 36 像素的圆形里认得出；简介见 `运营/账号资料.md`。视频里的品牌字样、片尾的关注理由要和简介说的一致；改动要记日期，方便对比主页访问和涨粉。
- **画幅**：从第 02 期起，母片一律横屏 16:9（1920×1080，30 fps，用户要求）。第 01 期保持竖屏 9:16，不改。
- **抖音也发横版，不再做竖版**（用户 10-29："竖排观感不佳"）。第 04、05 期做过 1080×1920 竖版包装（`videos/004-random-walk-vertical`、`005-regression-vertical`），但第 05 期用户发的是横版，2 秒跳出 36.85%，和第 04 期竖版的 36.68% 一样：2 秒跳出降下来靠的是开头，不是竖版。
- **第 06 期起的整体改版**（对照爆款的拆解，见 `运营/爆款拆解.md`；用户说"得迭代，不然做不起来"）：
  - **先演，后命名**：开头是一个能让观众跟着猜的小场景，末尾一句问"你"；片名卡放在 6–15 秒。**不在开头给答案**（第 04、05 期第 0 帧给答案，2 秒跳出降了一点，但完播和涨粉没变）。第一句字幕要在第 0 帧就完整显示。
  - **字幕**：每句 ≤ 18 字，每分钟 140–240 字，留出没有字幕、让模拟自己跑的段落。用 `node engine/caption-density.mjs videos/<期>` 检查（第 05 期是每分钟 297 字、最长 35 字）。
  - **一句一动作**：字幕说什么，屏上就真的发生什么；不写配着静止画面的句子。
  - **画面语法**用 `engine/film.js`：逐字显影（`developText`）、闪白、尘埃、片名卡、左上章节标（`drawChapter`，含问→算→想）、右上"分母表"（`drawDenominator`）。不用弹跳（outBack）和从屏外滑入；强调靠亮度和金色，不靠放大。
  - **颜色是词汇**：每期在 `style.js` 写清每种颜色的意思，全片不破例（第 06 期：冰蓝 = 飞机/已知，白 = 看得见的弹孔，红 = 看不见的/错的，金 = 答案/分母）。
  - **母题 + 回扣**：全片一个看得见的母题，结尾回到开场画面，最后一句呼应片名。
  - **事实上屏**：年份、地点、人名、原题直接上屏；传说标"据说"，示意标"示意模拟"；片尾放文献线索。
- **流程**：先在 `分镜.md` 写分镜，再分模块实现，用 `--preview` 抽帧检查，完整渲染后用 `engine/inspect.mjs` 验证，用 `--cover` 导出封面。**默认直接交完整期**（用户 10-29："你继续做就行了我直接发"），用户拿到就发，所以交付前自己把事实、数字、画面、字幕全检查一遍，并在 `运营/数据复盘.md` 写好标题、描述、置顶评论。只有方向大改时才先给 30–45 秒样片。
- **音效**（第 06 期起）：每期自带音效轨（`engine/sfx.js`：嗒、掠过、钟声、低击、打字机、成片的雨点声），场景写 `audio()`，渲染时加 `--wav` 另出 `-音效.wav`，用户在剪映电脑版里叠自己的音乐。音效不用有调性的旋律，免得和音乐打架；`audioPeakDb: -3`。各段落仍从 100 BPM 的小节线开始（1 小节 = 2.4 秒）。只调音效时用 `--audio-only`。
- **时长与价值**（用户决定，第 05 期起）：时长可以长（2–3 分钟没问题），重点是把内容做好、给观众带来真正有用的东西。不为了完播率砍内容。关注理由、评论问题不能只放片尾（发布文案、置顶评论都要有）。
- **"有用"的标准**：每期除了"原来如此"，还要给观众一个能带走的方法或判断标准（第 05 期：看到"做了 X 之后就变好了"，先问"不做 X 会不会也变好"；第 06 期：听到成功经验，先找没回来的飞机、数分母）。
- **形式**：不配音；中文字幕为主，下面一行英文斜体；先讲清"为什么"，再给反转。
- **可信度**：随机种子和模型参数在第一次运行前定好、结果不挑；片中数字一律从模拟结果读取；事实和实测结果写进该期的 `分镜.md`，供发布前核对。只用来画图的样本要和计数的实验分开种子。
  - 画面上的算式要对得上：差值、拆分都用**四舍五入后**的数来算（第 05 期的 `luck()`、`gain()`）。
  - 事先定好的规则挑出了"反例"时，不另挑一个"听话"的，改用整组平均，并在 `分镜.md` 里写明。展示个例时按事先定的规则取（第 06 期的 12 架"没回来的飞机" = 模拟里前 12 架被击落的）。
  - 标题、封面里的百分比要说清是谁的百分比。
  - 流传的故事和真实记载分开写（第 06 期：沃尔德的备忘录是真的，"军官要在洞多处加装甲"那段对话没有可靠记载）。
- **不留空屏**：每段一开始就要有画面内容，不能只有标题等 3 秒。
- **数据**：用户发来的后台数据记进 `运营/数据复盘.md`（原始数据表 + 判断 + 下次对比哪个数）。每期固定看：平均播放时长、2 秒跳出、5 秒完播、涨粉、收藏。之后每期只改一个大变量。
- **方向**（第 04 期起，用户要求）：内容往**心理、哲学**方向靠。题目仍用代码真实计算，但最后落到一个关于人、关于选择的问题上。引申的观点要和数学结论分开标注（"想一想"卡片 + 片尾说明"是我们的引申"）。选题优先认知心理（B 站前 100 里平均效果最好），标题里放一个具体数字。
- **系列风格**（第 04 期起，第 06 期改用 `engine/film.js` 的画法）：
  - 三段式「**问 → 算 → 想**」，显示在左上章节标里。
  - 收尾固定栏目「**算完了，想一想**」（`drawThinkCard`）：思源宋体 + 暖色纸面，最后一句是给观众的观点题。
  - 评论区问题：第 04 期的二选一（"你是醉汉，还是鸟？"）和第 05 期的讲经历（"说说你挨骂之后……"）评论都是 0。第 06 期试打一个字母就能答、有标准答案的题（"装甲加在 A、B 还是 C？"），放进文案和置顶评论，看数据再定。
  - 每期实现 `cover()`，用 `drawCover` 出 16:9 / 4:3 / 3:4 三张封面。**封面文字写一个问题，不写答案**：第 05 期用户自己做的封面"严师出高徒 / 是错觉吗"（一句熟悉的话 + 问号），跑出了目前最好的数据（收藏率是其他几期的 3–4 倍，见 `运营/数据复盘.md` 复盘 4）。
  - 开头就让观众知道和自己有关（第 05 期题目人人都经历过）；题材离生活远的（二战飞机），在片名卡副题里先点明和观众的关系（第 06 期："你刷到的成功经验，都是飞回来的"）。
- **选题顺序**：01 扔针算 π → 02 三门问题 → 03 生日问题 → 04 随机游走 → 05 回归均值 → 06 幸存者偏差（《弹孔》）→ **07 平均数的骗局**（第 06 期片尾已预告："all in 的人平均变成本金的 7 倍多，为什么 63% 的人亏了钱？"，用第 06 期同一个模型讲均值和中位数、一个人的十年和一万人的平均）。
